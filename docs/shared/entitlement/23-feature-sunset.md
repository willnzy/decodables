## 一、下线类型

### 1.1 功能类型分类

| 类型 | 说明 | 处理方式 |
|------|------|----------|
| 独立功能 | 不影响其他功能的独立模块 | 直接下线 |
| 依赖功能 | 有其他功能依赖 | 需先迁移依赖 |
| 数据功能 | 涉及用户数据 | 需提供数据导出 |

## 二、下线流程

### 2.1 标准流程 (90 天)

```
Day -90: 决策公告
├── 产品内公告
├── 邮件通知所有受影响用户
└── 更新帮助文档

Day -60: 功能标记
├── 功能入口显示 "即将下线" 标签
├── 新用户不再开放使用
└── 存量用户继续使用

Day -30: 迁移期
├── 提供替代方案
├── 提供数据导出工具
└── 每周提醒邮件

Day -7: 最后警告
├── 强制弹窗提醒
└── 每日提醒邮件

Day 0: 正式下线
├── 功能入口移除
├── 数据保留 30 天
└── 发送下线确认邮件

Day +30: 数据清理
└── 删除功能相关数据
```

### 2.2 紧急下线 (安全问题)

```
Day 0: 立即下线
├── 关闭功能 (Kill Switch)
├── 发送紧急通知
└── 说明原因和补偿

Day +7: 后续处理
├── 评估影响
├── 提供补偿方案
└── 如可修复则重新上线
```

**公告通知**:
```

内容:

我们决定于 [日期] 下线 XXX 功能。

原因: [简述原因]

您需要做的:
1. 在 [日期] 前导出您的数据
2. 了解替代方案: [链接]
```

```
过期后数据将无法恢复。
```

## 四、数据迁移

### 4.1 数据导出

为用户提供一键导出:
- 导出格式: JSON / CSV
- 导出范围: 该功能所有用户数据
- 导出方式: 邮件发送下载链接

### 4.2 数据保留

| 阶段 | 数据状态 |
|------|----------|
| 下线前 | 正常可用 |
| 下线后 30 天 | 只读，可导出 |
| 30 天后 | 永久删除 |

## 五、Feature Flag 配置

### 5.1 下线状态控制

```json
{
  "feature_key": "deprecated_feature",
  "status": "sunset",
  "sunset_config": {
    "announcement_date": "2026-01-01",
    "sunset_date": "2026-04-01",
    "hide_from_new_users": true,
    "show_deprecation_warning": true
  }
}
```

### 5.2 状态流转

```
active → deprecated → sunset → removed

active: 正常使用
deprecated: 显示下线警告，新用户不可见
sunset: 功能禁用，数据只读
removed: 完全移除
```

## 六、补偿方案

### 6.1 补偿类型

| 情况 | 补偿方式 |
|------|----------|
| 正常下线 | 无补偿 (提前 90 天通知) |
| 提前下线 | 按剩余时间比例退款或补偿积分 |
| 紧急下线 | 全额退款或等值积分 |

### 6.2 补偿计算

```
提前下线补偿:
补偿金额 = 月费 × (剩余天数 / 30)

紧急下线补偿:
补偿积分 = 功能相关消耗积分 × 2
```

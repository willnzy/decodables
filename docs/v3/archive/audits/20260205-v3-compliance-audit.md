### 2.2 ⚠️ 需要改进的内容

#### A. 元数据格式不统一

**问题**: 两种不同的元数据格式混用

**格式 1** (完整版):
```markdown
> **版本**: 1.0.0
> **创建日期**: 2026-02-05
> **最后更新**: 2026-02-05
> **状态**: 🟢 已验证
> **同步范围**: [fullstack]
> **对应代码**: path/to/code
```

**格式 2** (简化版):
```markdown
**验证状态**: 🟢 已验证  
**同步范围**: [fullstack]
```

**建议**: 统一使用格式 1 (完整版)，但允许省略可选字段

#### B. 占位符 README 过多

**问题**: 约 30 个 README 仅有目录说明

**示例**:
```
/06-growth/acquisition/README.md     - 18 行
/06-growth/monetization/README.md    - 18 行
/05-business/entitlement/current/README.md - 25 行
```

**建议**: 
- 保留作为目录索引，但标注 `🟡 待完善`
- 添加"计划文档"列表 (已部分实现)

#### C. 缺少代码来源的文档

**问题**: 部分文档缺少 `数据来源` 或 `对应代码` 字段

**受影响文档** (约 30 个):
- `06-growth/` 目录下大部分文档
- `11-reference/` 部分文档
- `public/` 用户文档

**建议**: 
- 业务/运营类文档可省略代码来源
- 工程类文档必须标注代码来源

#### D. 同步标注覆盖不完整

**问题**: 部分 `[fullstack]` 文档未同步到前端仓库

**检查方法**: 比对后端和前端 v3 目录

**建议**: 
- 创建同步检查脚本
- 在 commit 时自动检查

### 2.3 ❌ 不符合原则的内容

#### A. tmp/ 目录存在工作文件

**问题**: `tmp/working/` 存在历史审计报告

**文件**:
- `20260205-v2-v3-coverage-audit.md` (451 行)
- `20260205-v3-audit-report.md`

**规则**: "用完删除或同步后删除"

**建议**: 
- 如果审计已完成，应归档或删除
- 如果仍在使用，可保留

#### B. planned/ 和 current/ 子目录使用不一致

**问题**: `05-business/entitlement/` 有 `current/` 和 `planned/` 子目录，但大部分内容直接放在主目录

**当前结构**:
```
entitlement/
├── current/          # 仅有 README
├── planned/          # 仅有 README
├── policy-rules.md   # 在主目录
├── promotions.md     # 在主目录
└── ...
```

**规则**: "已实现的放在 current/，待实现的放在 planned/"

**建议**: 
- 方案 1: 将所有已实现文档移到 `current/`
- 方案 2: 删除 `current/` 和 `planned/` 子目录，在文档内标注状态
- **推荐方案 2** (简化目录结构)

# MagicZine AI - 全栈开发规格说明书 (v1.7 - 生产级安全稳定版)

本文档是项目的唯一真理来源 (SSOT)。涵盖数据库 Schema、存储策略、后端 API 规范及前端开发指令。

## Part 1: 数据库与存储设计 (Supabase)

请在 Supabase SQL Editor 中执行以下建表语句，并配置 Storage。

### 1.1 核心表结构 (SQL)

    -- 1. 用户档案表 (User Profiles)
    create table profiles (
      id text primary key, -- 对应 Clerk user_id
      email text,
      username text,
      avatar_url text,
      credits int default 0,
      tier text default 'free', -- 'free', 'starter', 'pro'
      stripe_customer_id text,
      role text default 'user', -- 'user', 'admin'
      created_at timestamptz default now()
    );

    -- 2. 积分流水表 (Financial Ledger)
    -- [核心] 记录每一笔资金/积分变动，用于财务对账
    create table credit_transactions (
      id uuid default gen_random_uuid() primary key,
      user_id text references profiles(id) not null,
      amount int not null, -- 变动值 (+100, -50)
      balance_after int not null, -- [核心] 变动后的余额快照 (Running Balance)
      type text not null, -- 枚举见下方
      description text, 
      created_at timestamptz default now()
    );
    -- type 枚举: 'signup_bonus', 'purchase', 'subscription_grant', 'subscription_renewal', 'generation', 'download_pdf', 'admin_adjustment'

    -- 3. 项目表 (User Projects)
    create table projects (
      id uuid default gen_random_uuid() primary key,
      user_id text references profiles(id) not null,
      title text default 'My Magic Story',
      canvas_data jsonb default '{}'::jsonb, -- Fabric.js JSON
      thumbnail_url text,
      last_downloaded_hash text, -- 校验修改
      is_deleted boolean default false, -- 软删除
      created_at timestamptz default now(),
      updated_at timestamptz default now()
    );

    -- 4. 素材资源表 (Asset Library)
    -- [核心] 支持用户上传及 AI 生成图片的复用
    create table assets (
      id uuid default gen_random_uuid() primary key,
      user_id text references profiles(id) not null,
      url text not null, -- Storage URL
      type text not null, -- 'user_upload' | 'ai_generated'
      prompt text, -- AI 生成时的提示词 (可选)
      is_deleted boolean default false,
      created_at timestamptz default now()
    );
    create index idx_assets_user_id on assets(user_id);

    -- 5. 行为日志表 (User Behavior Logs)
    -- [核心] 仅记录普通用户的 C 端行为，用于漏斗分析
    create table activity_logs (
      id uuid default gen_random_uuid() primary key,
      user_id text references profiles(id),
      action text not null, 
      metadata jsonb, -- 记录 IP, 来源, 错误信息
      created_at timestamptz default now()
    );
    -- action 枚举: 'login', 'click_checkout', 'payment_success', 'create_project', 'download_pdf', 'submit_support_ticket'

    -- 6. 客服与运营记录表 (Support & Admin Ops)
    -- [核心] 记录工单 + 所有 Admin 后台操作 (审计用)
    create table support_tickets (
      id uuid default gen_random_uuid() primary key,
      user_id text references profiles(id), -- 目标用户
      admin_id text references profiles(id), -- 操作管理员 (若为用户提交工单则为NULL)
      category text not null, -- 'ticket_submission', 'admin_adjustment_credits', 'admin_change_tier'
      content text, -- 工单内容 或 操作理由
      metadata jsonb, -- {old_val: x, new_val: y}
      status text default 'closed',
      created_at timestamptz default now()
    );

### 1.2 存储桶配置 (Storage Buckets)
*请在 Supabase Dashboard 创建以下 Buckets 并设置 Policy：*
1.  **`user-uploads`**: Public=True。Policy: Authenticated Upload, Public Read。
2.  **`generated-images`**: Public=True。Policy: Service Role Upload (Backend), Public Read。
3.  **`generated-pdfs`**: Public=False。Policy: Only Owner Download (Signed URL)。

### 1.3 权限 (RLS)
* **Profiles/Projects/Assets**: 用户仅可读写 `id = auth.uid()` 的数据。
* **Admin**: `role = 'admin'` 的用户拥有全库读写权限。

## Part 2: 后端安全实施规范 (Security Implementation)

**此部分优先级最高，必须在编写 API 逻辑前实施。**

### 2.1 全局安全配置
1.  **CORS**: 
    * Dev: `allow_origins=["http://localhost:3000"]`
    * Prod: `allow_origins=["https://your-domain.com"]` (严禁使用 `*`)
2.  **Rate Limiting (限流)**:
    * 引入 `SlowAPI` 或 Redis。
    * 对 `/api/generate/*` 接口实施限制 (如: 10次/分钟)，防止脚本恶意刷光 API 额度。

### 2.2 鉴权与守卫 (Middleware)
1.  **强制 JWT 验证**: 
    * 创建 `get_current_user` 依赖。验证 `Authorization: Bearer <token>` 签名 (Clerk)。
    * 验证失败直接返回 `401 Unauthorized`。
2.  **Admin 守卫**:
    * 创建 `require_admin` 依赖。检查 `user.publicMetadata.role === 'admin'`。
    * 验证失败直接返回 `403 Forbidden`。

### 2.3 核心业务安全
1.  **原子化扣费 (Atomic Transactions)**:
    * 在扣除积分时，**必须**使用数据库事务。
    * 逻辑: `Start Tx` -> `Select credits For Update` (锁行) -> `Check Balance` -> `Deduct` -> `Commit`。
    * 严禁依赖前端传来的 "用户有钱" 状态。
2.  **Webhook 签名验证**:
    * 所有 Webhook (Stripe/Clerk) **必须**验证 Header 中的官方签名 (`Stripe-Signature`, `svix-signature`)。
    * 签名无效直接返回 `400`。

## Part 3: 后端接口规范 (FastAPI)

**通用规范**:
* 所有列表接口需支持分页参数: `?page=1&limit=20`。
* 错误响应格式: `{ "detail": "ErrorCode: Message" }` (如 `CREDITS_INSUFFICIENT: Need 50 credits`)。

### 3.1 系统与用户

| 方法 | 路径 | 描述 | 逻辑细节 |
| :--- | :--- | :--- | :--- |
| **GET** | /health | **系统健康** | 返回 `{"status": "ok"}` (用于 Railway 保活)。 |
| **POST** | /api/webhooks/clerk | **注册回调** | [Sec] 验签 -> 插入 profiles -> 赠送积分 -> 记流水。 |
| **GET** | /api/user/me | **用户信息** | [Auth] 返回 UID, Avatar, Credits, Tier。 |
| **GET** | /api/user/history | **积分历史** | [Auth] 分页查询 `credit_transactions`。 |
| **GET** | /api/user/assets | **素材库** | [Auth] 分页查询 `assets` 表。 |

### 3.2 核心业务 (Projects & Gen)

| 方法 | 路径 | 描述 | 逻辑细节 |
| :--- | :--- | :--- | :--- |
| **GET** | /api/projects | **项目列表** | [Auth] 分页查询 `is_deleted=false` 的摘要。 |
| **GET** | /api/projects/{id} | **项目详情** | [Auth] 获取完整 `canvas_data`。 |
| **POST** | /api/projects | **创建项目** | [Auth] 初始化 -> 记 `activity_logs`。 |
| **PUT** | /api/projects/{id} | **自动保存** | [Auth] 更新 JSON。 |
| **DELETE**| /api/projects/{id} | **删除项目** | [Auth] 软删除 (`is_deleted=true`)。 |
| **POST** | /api/generate/images | **AI 生图** | [Auth] [RateLimit]<br>**1. 风控**: 检查 Prompt (NSFW/IP黑名单)。<br>**2. 事务**: 检查余额 -> 锁定 -> 扣费。<br>**3. 生成**: 调用 AI。<br>**4. 存储**: 存入 Storage & `assets`。<br>**5. 记录**: 记流水。 |
| **POST** | /api/generate/pdf | **下载 PDF** | [Auth] 对比 Hash -> 智能扣费(事务) -> 记 `activity_logs`。 |

### 3.3 支付系统 (Stripe)

| 方法 | 路径 | 描述 | 逻辑细节 |
| :--- | :--- | :--- | :--- |
| **POST** | /api/payment/checkout | **购买链接** | [Auth] 返回 Stripe URL。Metadata: `user_id`, `plan_type`。 |
| **POST** | /api/payment/portal | **订阅管理** | [Auth] 创建 Stripe Customer Portal。 |
| **POST** | /api/webhooks/stripe | **支付回调** | [Sec] 验签。<br>**1. `checkout...`**: 首次购买/订阅 -> 加分/改等级 -> 记流水。<br>**2. `invoice.payment_succeeded`**: 订阅续费 -> 发放月度积分 -> 记流水。 |

### 3.4 客服与管理 (Admin)

| 方法 | 路径 | 描述 | 逻辑细节 |
| :--- | :--- | :--- | :--- |
| **POST** | /api/support/email | **提交工单** | [Auth] 发邮件 -> 存 `support_tickets`。 |
| **GET** | /api/admin/users | **搜索用户** | [Admin] 参数 `?query=email_or_uid`。 |
| **GET** | /api/admin/user/{uid} | **用户审计** | [Admin] 获取全量信息 (Profile+History+Logs+Tickets)。 |
| **POST** | /api/admin/credits/adjust| **调积分** | [Admin] 事务改余额 -> 记流水 -> 记 `support_tickets`。 |
| **POST** | /api/admin/tier/update | **改等级** | [Admin] 改等级 -> 记 `support_tickets`。 |

## Part 4: 前端开发指令 (给 Cursor)

请使用 **Next.js 15 (App Router)**, **Shadcn UI**, **Tailwind CSS**, **Clerk** 实现。

### 4.1 全局与导航
> "1. 配置 `ClerkProvider`。
>  2. **API Client**: 封装 Axios，自动注入 Clerk Token，统一拦截 401 (跳登录) 和 402 (弹充值窗) 错误。
>  3. **Navbar**: 显示用户头像 + '⚡ {credits}'。"

### 4.2 用户仪表盘 (/dashboard)
> "1. **Header**: 显示等级。若为付费会员，显示 'Manage Subscription' 按钮 (调用 `/api/payment/portal`)。
>  2. **Credit Actions**:
>     * **'Buy'**: 调用 `/api/payment/checkout`。
>     * **'History'**: 弹窗表格显示积分流，必须展示 **Balance After**。
>  3. **My Projects**: 网格展示，支持翻页 (Pagination)。包含 Edit/Delete 按钮。"

### 4.3 编辑器 (/editor/[id])
> "1. **Load Data**: 调用 `/api/projects/{id}`。
>  2. **Media Library (Tab)**: 
>     * **Uploads**: 上传至 Supabase Storage `user-uploads`。
>     * **History**: 分页加载 `/api/user/assets`，支持拖拽上画布。
>  3. **Safety UI**: 若生图接口返回 400 (NSFW)，前端需弹出 Toast 警告用户 'Content Policy Violation'。
>  4. **Download**: 触发智能扣费。若余额不足，自动弹窗引导充值。"

### 4.4 客服支持组件 (全局悬浮)
> "悬浮 'Help' 按钮。
>  1. **WhatsApp**: 跳转链接。
>  2. **Email**: 弹窗表单。提交调用 `/api/support/email`。"

### 4.5 管理员后台 (/admin)
> "1. **Guard**: 路由级检查 `role === 'admin'`。
>  2. **User Search**: 顶部搜索框。
>  3. **User Detail (三栏布局)**:
>       * **Left**: Info + Actions (Adjust Credits / Change Tier)。
>       * **Center**: Financial Ledger (`credit_transactions`)。
>       * **Right**: Audit Logs (`activity_logs`) & Ops Records (`support_tickets`)。"
